# Engagement playbooks

Each path is a suggested set of decision-oriented deliverables. Skip irrelevant work; never manufacture missing evidence.

| Trigger | First useful outputs | Only if warranted |
| --- | --- | --- |
| Company name | Entity resolution, dossier, business model, top uncertainties | Deep competition, financial review, operating model |
| Client brief or RFP | Objective, authority/scope, challenge map, current alternatives | Proposal, workplan, capability roadmap |
| Industry | Defined market boundary, actors, value chain, changes, source coverage | TAM/SAM/SOM, market-entry thesis |
| New venture | Customer job, opportunity hypothesis, options, smallest test | Venture thesis, stage-gate capital, launch plan |
| Existing product | Desired outcome, interview plan, opportunity hypotheses | PRD, experiments, launch and measurement |
| Transformation | Current capabilities, bottlenecks, decision rights | Target operating model, adoption plan |
| Transaction | Entity and instrument, diligence requests, risk register | Financial model, investment memo, renegotiation |
| Specific deliverable | Audience, purpose, source ledger, draft, independent QA | Larger strategy only if necessary for correctness |

## Internal stage contract

Every meaningful stage should declare: `inputs`, `method`, `responsible role`, `expected artifact`, `evaluation standard`, `unresolved items`, `permission class`, `next decision`. A stage may be skipped with an explicit rationale. Do not execute external actions because a stage label happens to be `act`.
