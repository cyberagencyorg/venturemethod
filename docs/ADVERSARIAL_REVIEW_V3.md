# Adversarial system and epistemic audit, v0.3 (2026-10-19)

## Critical conclusions

1. **No full ecosystem coverage claim is valid.** We have nine upstream ecosystem entries plus thirty-four method metadata entries, not a verified union of upstream skill implementations, nor enough evidence to declare any agent proficiency.
2. **v0.2 mistook structure for expertise.** Successful file validation does not prove correct market analysis, pricing research, causality, venture diligence, or skill selection. Synthetic fixture tests are necessary but inadequate.
3. **v0.2's single-writer hash chain is not collaborative change governance.** Projections can be replayed, but there is no source refresh, identity/merge semantics, secure approval, semantic reconciliation, or client tenancy service.
4. **A framework selector must not become an arbitrary score generator.** The v0.3 comparator uses a declared goal and evidence class. It does not claim to automate expert judgment. Do not add invented high-precision methodology scores.
5. **Ontology completeness must remain falsifiable.** Typed nouns alone do not capture negative evidence, alternate explanations, intervals, mutually exclusive hypotheses, effective dates, conflicting perspectives, and authorization boundaries.
6. **Licenses differ materially.** MIT and Apache-2.0 still require conditions; Dean's CC BY-NC-SA imposes restrictions; Anthropic's individual skill files may vary. Source discovery is never automatic installation.
7. **An output isn't static just because it's exported.** Canonical knowledge evolves. Approved snapshots, dependencies and lifecycle rules are essential. This is a product invariant, not an enhancement.
8. **Methods disagree.** JTBD variants, customer interviews versus quantified outcomes, Wardley mapping versus causal-loop modeling, and scenario planning versus forecasts have different evidentiary requirements. A unified taxonomy must preserve rather than erase those differences.
9. **Universal workflows become procedural bloat.** Frameworks should be opt-in candidates selected for explicit problems with empirical rejection criteria, human override and clear cost limits.
10. **Cross-client learning is a privacy hazard.** Any global skill improvement must use permissioned sanitized evaluation cases, never raw client transcripts or proprietary decision records.

## New verified code claims

- `config/frameworks-v3.json`: 34 original framework metadata records with source, task fit, requirements, cautions and expected output; no upstream skill text copied.
- `src/va/methodology.py`: validate metadata, compare matching methods with explicit evidence maturity, no automatic winner; local deterministic check only.
- `src/va/change_model.py`: draft claim successor and conservative downstream dependency traversal, no auto-adoption; source references constrained to engagement.
- `tests/test_v03.py` and `tests/test_v03_change.py`: structural tests of selection, no false runtime claims, lineage and stable prior decisions. These do **not** benchmark AI outputs or prove production safety.

## What should be built next, by dependency

**P0: Inventory and contracts.** Pin source SHA/version per upstream source, compare every skill/workflow against domain competence contracts. Trace what is incorporated/delegated/left out. Expand from general risk labels to measurable acceptance rubrics.

**P0: Trustworthy knowledge lifecycle.** Typed identifiers, semantic changes, evidence versioning, explicit current/retired state, conflicting hypotheses, impact relationships, permissioned approval, refresh cadence and materialized views. Build and test under concurrent writers before accepting confidential commercial engagements.

**P1: Evidence acquisition and research.** Authorized read adapters with freshness, dates, official-source preference, source rights, de-duplication and contradiction-aware synthesis. Research should be able to conclude "insufficient evidence" and stop.

**P1: Real evaluation.** Baseline vs skill vs workflow, blinded reviewer, model/harness variation, fact checks against held-out data, professional expert judgment, economic value, cost and negative/stop outcomes. The comparator should get penalized for unnecessary methods.

**P2: Artifact adapters.** Versioned decision memos, sheets, slides, prototypes, dashboards, market maps and contracts with lineage/manifests. Human approval required for external delivery.

**P2: Execution bridges.** Only approved, scoped plans may issue tasks to Open ASS, Creative Studio and other systems; each adapter must return artifacts and independent verification to the knowledge graph.

## Failure-oriented acceptance suite

- A business with no need for a software product must not be routed to building software.
- A stale market research source must trigger review of relevant dependent outputs, not a global regen.
- Two contradictory sources must not be collapsed into an unsupported averaged claim.
- A zero-customer-data case must not generate confidence-rich personas, market share or user interview quotations.
- A source permission downgrade must block future materialization of the source into an output.
- A method cannot be called implemented because its name occurs in a prompt or its README contains an example.
- A claimed 10/10 skill must show reproducible comparative expert and automated evidence and limits.
- Updating a framework must not mutate the methods used for a previously approved engagement snapshot without an explicit migration decision.
